# Shared container tracking — implementation boundaries

Phase 1 implements the standalone Sea Legend source-access proof; Phase 2 implements exactly **Container** and **ContainerEvent**, with forward migrations and model validation. See [current schema/rules](DATA_MODEL.md) and [source limitations](OPERATIONS_RUNBOOK.md#phase-1-carrier-source-proof). Phase 3 implements bilingual manual Container admin and manual events, publication controls and archiving. Phase 4 adds explicit retrieval/validation/save with optional Groq port labels and claim/version checks. Phase 5 adds the bounded command, attention indicators and inactive systemd package. Phase 6 implements approved-snapshot public lookup, bilingual source-time/status/timeline display, fail-closed abuse protection and a default-off validated-carrier publication gate. Phase 7 provides complete synthetic lifecycle and installed-image/recovery acceptance; live schedule/deployment activation remains Phase 8. The following sections describe boundaries; local tests do not establish those later operational outcomes. Customer accounts, customer rows, per-person shipments/products and document/AI review records remain excluded.

## Container

Keep separate fields for the carrier's B/L/search reference and the actual container identifier; neither is interchangeable with vessel/voyage or an internal database ID. Record source website and supported source adapter, equipment quantity/type, loading/discharge codes and reviewed bilingual route labels, vessel/voyage, raw carrier status plus reviewed bilingual status. Unknown facts remain null/unknown.

Represent departure/arrival separately and distinguish **estimated versus actual** explicitly. Preserve each raw timestamp and its displayed precision/type, plus a nullable source timezone and nullable normalized instant. If the source displays no timezone, retain it as an unzoned local datetime/text, label “timezone not supplied”, and leave the UTC instant empty. Never silently apply the application/business timezone or render it as an exact instant. Corrections retain provenance instead of upgrading an estimate to an actual fact.

Include independent manual notes, archive flag/time and deliberate publication control. Public lookup returns only reviewed saved fields for published, non-archived records. Last refresh attempt/success and a bounded safe error code/summary are separate; errors omit secrets, page bodies and identifiers. Failed retrieval retains the last good facts, their source/last-success time and manual notes. Carrier refresh never overwrites independent manual notes or implicitly publishes a record.

## ContainerEvent

Reference Container; record origin (`carrier` or `manual`), raw source status/text/time/timezone/precision, reviewed English/Arabic title/detail, optional source event identifier, observed/retrieved time, publication flag and stable dedupe key. Prefer a source-provided ID; otherwise hash a canonical tuple of container, source, raw event time, status/location/text. Repeated retrieval updates provenance/last-seen safely instead of duplicating a milestone. Manual events have their own identity and cannot be overwritten by carrier events. Unknown event timezone follows the same nullable-instant rule.

## Retrieval boundary and bounded command

Prove supported source access first: documented carrier interface/export before an HTTP adapter, browser retrieval only if necessary and permitted. Use a host allowlist, bounded redirects/time/content, explicit timeouts and safe diagnostics; do not let an administrator-provided URL become unrestricted SSRF. Authentication/CAPTCHA/terms/source availability must be evaluated against the actual source. Do not promise unattended extraction before that proof.

Phase 5 implements a bounded active/single-container command through the same Phase 4 retrieval/validation/save service. Its systemd oneshot/timer package proposes daily 09:00 Asia/Kabul; it is not installed or enabled before Phase 8. Per-container claims protect concurrent saves, and a shared batch lock prevents competing command runs. Facts/events save atomically, attempts and successes remain separate, and unchanged labels are reused. Public page views do not initiate retrieval or AI.

Groq may receive bounded, already retrieved content for structured facts/translation. Its API is not a web browser. Treat page content as untrusted data, never instructions; select a supported model/output mode, validate with a strict local schema, preserve source evidence and distinguish missing/uncertain facts. Reject unsupported facts and malformed output, never invent dates/statuses. Page views perform no publication, manual-note overwrite or provider transmission. Automatic carrier publication requires an explicitly opted-in, already manually reviewed parent; it never includes unreviewed AI Arabic labels or unknown/undated carrier stages.

The initial cleanup did not query or seed the owner's real reference. The owner subsequently authorized Phase 1: bounded carrier-only live lookups now have private evidence. No real reference is committed, seeded, published or sent to Groq. Later integrated/provider operations require their separately approved phase.
